Optimizing Heavy GeoJSON Files for Faster Web Performance

11 min read · Simplification · Vector tiles · abcGEO Editorial

Answer-first

Speed up web maps by shrinking GeoJSON (simplify geometries, drop unused properties), fetching only the viewport, and moving dense layers to vector tiles when FeatureCollections stop scaling.

This cluster article supports Pillar 2: Modern Web Mapping & Spatial Analysis and overlaps intentionally with Pillar 1: Geographic Data Conversion— because performance problems often start as format and precision problems.

Why “valid” GeoJSON still feels slow

Answer-first

Browsers pay for download size, JSON parse time, and per-vertex render work. A correct 40 MB FeatureCollection can still fail product UX on mid-range phones.

Desktop GIS hides the cost: QGIS can chew through detailed polygons while you grab coffee. Leaflet and even MapLibre will fight the main thread if you ask them to hydrate every vertex at once. Optimization is not cheating—it is matching detail to zoom and device.

Step 1: Measure before you tune

  • Record file size (raw and gzipped) and feature count.
  • Note average coordinates per polygon ring.
  • Profile first paint / interaction delay on a mid-tier mobile device or throttled CPU.
  • Confirm the data is even in the right format—see GeoJSON structure and converters on tools.html.

Step 2: Trim attributes aggressively

Answer-first

Most exports include columns the map never shows. Keep popup fields only; move analytics attributes to an API keyed by feature id.

If you flattened data with GeoJSON to CSV for QA, it is easy to spot unused columns. Delete them in GeoPandas or SQL before re-exporting web GeoJSON.

Step 3: Simplify geometries by zoom intent

Answer-first

Cartographic simplification removes vertices that do not change the shape at the target zoom—preserving topology when boundaries must still share edges.

import geopandas as gpd

gdf = gpd.read_file("parcels.geojson").to_crs(4326)
# tolerance is in degree units here—tune carefully
gdf["geometry"] = gdf.simplify(0.00008, preserve_topology=True)
gdf = gdf[gdf.geometry.notna() & ~gdf.geometry.is_empty]
gdf.to_file("parcels-simplified.geojson", driver="GeoJSON")

Start conservative. Visually compare against the source at city and neighborhood zooms. Invalid leftovers after simplify should be fixed—see the geometry pitfalls in Pillar 1’s conversion workflow.

Step 4: Fetch less with viewport queries

Even a simplified national dataset should not download on page load. Serve a feature API backed by PostGIS that accepts a bounding box and returns only intersecting features. Cache responses at the CDN when tiles are overkill but the layer is still large.

Step 5: Graduate to vector tiles

Answer-first

Vector tiles (MVT) stream zoom-appropriate geometry so MapLibre/Mapbox GL can render dense layers without parsing one giant GeoJSON document.

  • Build tiles offline with Tippecanoe-style pipelines when the dataset is relatively static.
  • Serve dynamic tiles from PostGIS-oriented tile servers when filters and freshness matter.
  • Keep GeoJSON for small layers—points of interest, editorial callouts, and admin tools.
Rule of thumb: if gzipped GeoJSON exceeds roughly 1–2 MB for a layer users must interact with immediately, evaluate tiling or progressive loading before adding more map features.
